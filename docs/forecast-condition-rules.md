# Forecast condition rules

## 条件数据列表同步规则

`条件数据列表` 必须始终展示当前系统中的全部预测条件，不能只展示最早实现的一部分条件。

- 新增、删除或重命名任何预测条件时，必须同步更新：预测主界面、条件数据列表、GitHub Actions 自动检查/通知逻辑，以及相关测试。
- `条件数据列表` 打开时，所有预测条件默认都不勾选；用户必须主动选择需要查询的条件后再执行。
- 条件数据列表中的默认阈值应与预测主界面 / GitHub Variables 使用同一套配置来源；未配置仓库变量时才使用代码中的默认值。
- 对复合条件，条件数据查询必须按该条件本身的完整逻辑计算，而不能只比较原始指标值。例如：
  - 全球央行净购金趋势：最新季度相对前 N 季均值的提升幅度达到阈值，并满足连续上涨次数要求。
  - ISM 新订单急剧恶化：当前值低于 50，且较上个月下降幅度达到阈值。
- 条件数据列表的执行结果必须以当前勾选项为准；未勾选任何条件时不执行查询，并提示用户至少选择一个条件。

## ISM 新订单历史回测规则

ISM 新订单的条件数据查询必须保留足够长、连续的月度历史，使 2008 年金融危机和 2020 年新冠冲击可以参与同一套规则回测。

- 默认保留最近 30 年月度历史。
- 2015-03 及以前：使用固定的 FRED-MD 2015-04 vintage 历史快照；构建时从固定 commit 的镜像读取，并用 2008、2015 锚点校验列和值，避免错误文件或列偏移。
- 2015-04 至 2020-12：使用当时公布的 ISM Manufacturing New Orders 历史月度值作为连续桥接数据。
- 2021-01 至 2025-12：沿用 DBnomics ISM 历史序列。
- 2026-01 至最新月份：沿用 ISM 官方月报快照补齐最新值。
- FRED-MD 从 2016-06 vintage 起移除了 `NAPM`、`NAPMNOI`、`NAPMSDI` 等 ISM 序列，因此不得再把“当前 FRED-MD current.csv”作为这些 ISM 指标的历史源。
- 环比规则只能比较真正连续的两个自然月；如果历史序列出现月份缺口，缺口两侧不得计算环比、不得产生预测命中。
- 构建阶段必须验证月度连续性，并验证默认 10% 规则能够识别 2008 年金融危机和 2020 年新冠冲击中的典型急跌月份；验证失败时构建应失败，而不是静默发布不完整历史。

## 当前预测条件

当前系统包括：

1. NDX 距历史最高点回撤
2. VIX 恐慌指数
3. 美国失业率
4. 萨姆规则衰退指标
5. 全球央行净购金趋势
6. ISM 新订单急剧恶化

后续增加第 7 项及以后条件时，也必须自动遵循上述同步规则。
