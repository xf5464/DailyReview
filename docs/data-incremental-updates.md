# 全部数据的更新策略

45 个宏观指标都必须在 `scripts/data-update-policies.js` 中声明策略；新增指标遗漏策略会使构建和测试失败。构建将每项的首次建立、增量、回退、不可用，以及新增和修订观测数量写入 `.cache/data-update-report.json`。

## 序列增量

各指标独立判断历史基线是否存在，缺少某一项时只补齐该项，不能用其他指标的缓存代替其历史。日度及周度源从该项最后观测前 14 天开始请求，长期停更后也会补回缺失区间。月度请求保留 15 个月的原始值，以便 CPI、PCE 等同比计算；新值按日期覆盖旧值，其余历史保留。

行业集中度保留逐行业历史并合并近期数据；ETF 官方净值与未复权收盘价采用一致的有限观察数量，长期停更时扩大窗口。交易所换手率从已保存历史继续补齐，并限制并发。衍生指标保留计算所需的预热区间。未来经济日历是有效期快照，更新时替换，不能把过期事件追加进未来日历。

## 原始文件更新

所有 npm 数据准备及构建命令、Pages 构建、新闻刷新和成交额刷新工作流均加载条件请求缓存。CSV、网页、报告、备用源等完整文件支持 ETag/Last-Modified 时发送条件请求，304 直接复用经 SHA-256 验证的本地正文。固定 Git 提交中的原始历史文件在验证缓存后直接复用。正文损坏时重新请求，错误响应不能覆盖成功缓存；请求有超时，同一来源连续故障会快速失败，并由指标层保留上次有效数据。

必须区分“本地历史按日期增量合并”与“上游只发送新记录”。某些外部接口既没有日期筛选，也不支持 HTTP 条件请求：它们仍需要完整响应才能确认是否修订，不能声称这部分网络传输已变成逐条增量。请求日志 `.cache/source-responses/requests-*.jsonl` 明确记录首次、变更文件、304、不可变文件复用及失败，并记录实际响应字节数。

带身份凭证、Cookie、Range、调用方自行管理条件头，以及声明 no-store 的请求不进入共享缓存。新闻实时入口保持新鲜度；已有新闻按原流程按身份去重和复用翻译，不把实时榜单误当作不可变历史。

## 手动及离线数据

公募行业集中度继续按用户授权手动更新，复用原始披露及季度检查点，只计算需要补齐的季度，普通部署不启动采集。捆绑的历史快照只在文件内容变化时更新。

网页离线更新继续使用带内容指纹的逐年数据块和独立数据集，未变化的块复用，变化的块重新下载并校验；来源下载失败不等于零值，离线校验失败保留旧版。首次安装或缓存被清除后仍须建立完整基线。

GitHub Actions 同时持久保存图表历史、行业原始序列和原始条件响应。缓存不是永久档案，平台淘汰缓存后会安全补建；原始研究证据与正式静态数据不依赖此临时 HTTP 缓存存续。
