# 商品日报图片输入

企业微信商品日报复用 `scripts/render-a-share-report.py --market commodity`，按天然气、布伦特原油、黄金、白银、铜顺序发送五张合并PNG。每张图包含最新报价与时间、单位、合约身份、近3年高值及日期、动态五档回落表、五周期百分位和近一年曲线。最高值与日期同一行，仅数值绿色加粗，标题居中。此功能只在 `codex/market-report-wecom` 分支，主站指标保持原口径。

数据源延续现有任务：NG=F/BZ=F/SI=F/HG=F 为Yahoo提供的交易所滚动期货报价及同源日线，含换月；黄金仍为新浪XAU伦敦金现货。FRED天然气/布伦特现货及月度铜价无法满足用户指定的最新期货、日度连续历史和铜美元/磅口径，故不用于这些期货图，不以其补缺。Yahoo不可用时只接受同交易所、同单位、同历史口径且可核实的来源；不得使用CFD替代，缺数时明确报告未完成。

先写 `reports/commodity-chart-data.json`，再最后更新 `reports/commodity-daily.txt` 触发一次发送。不得仅更新文本而复用陈旧图表数据。JSON结构：

- `reportDate`：北京时间报告日期，YYYY-MM-DD。
- `indices`：空数组。
- `metrics`：恰好五项，code/name/unit/decimals依次为 NG=F/天然气/美元\/MMBtu/3、BZ=F/布伦特原油/美元\/桶/2、gold/黄金/美元\/盎司/2、SI=F/白银/美元\/盎司/2、HG=F/铜/美元\/磅/4。
- 各项包含 `tradingDate`（来源真实交易日D）、`sourceUrl`、`sourceLabel`、`instrument`（交易所品种和实际月份或伦敦金现货身份）、`quoteTime`（源真实时间及明确时区）、`priceBasis`（百分位按最新报价计算/按收盘价计算）、`historyBasis`（连续期货历史，含换月/伦敦金现货日线）。四个身份字段须为简短单行文字。
- `items`：D减1日历年至D含两端，升序唯一日期，至少200条有效日线。取已完成日线，排除D尚未完成的日线，加入本轮最新报价为D唯一观察；采用正式收盘时仅保留一次。不使用报告日期替代交易日。不把报价称为正式收盘。
- `drawdownReference`：`value`为完整同口径[D减3日历年,D]已完成日线及本轮唯一D报价的最大值，`date`为最近一次达到最大值的真实日期，`windowStart`/`windowEnd`为窗口两端，`sampleCount`为有效去重记录数（至少700），`sourceUrl`为完整历史来源。不得从近一年items计算3年高点，不使用盘中最高。D不同应分别计算。

回落从该近3年高值累计计算。回落小于30%显示10/15/20/25/30%，达到30%切换30/35/40/45/50%，达到50%切换50/55/60/65/70%，反弹同步恢复。原精度判断已达绿色、最近未达黄色、其余白灰；仅黄档显示从当前价再跌至目标价的比例。70%以上保持最后五档。报价和档位保留各品种精度。

文本首行严格 `商品价格日报｜北京时间YYYY-MM-DD`，之后每项以单独名称行开始，各项之间空一行。字段包括 `数值：带千位分隔及指定位数的报价+单位`、`数据日期：YYYY-MM-DD`、与JSON一致的四个身份字段各独占一行，再接原固定宽度五行百分位表，标签和顺序保持现有约定。文本只用于渲染核验，群内不再另发全文，无旧2000字节限制。五周期保留1/3/6个月、1/3年全部数据，使用原中秩算法及完整同源历史，不能把回落比例当百分位。

工作流先渲染并验证五张图，再验证所有图片顺序、PNG签名和每张小于2MiB，最后依次发送并记录每条errcode。5/5均errcode=0才报告完整成功；不重试不确定的部分发送。代码和样式更新不触发推送；仅报告文本更新或明确手动执行时发送。

验证：`python -m unittest discover -s test -p '*_test.py'`，并使用现有A股及美股报告渲染回归核对。
